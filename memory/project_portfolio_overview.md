Next.js 16 (App Router, TypeScript, Turbopack), Framer Motion, no Tailwind — plain CSS Modules. Site is a terminal/HUD-styled personal portfolio for [[user-profile]]. Four routes: `/` (about), `/creations`, `/reflections`, `/contact`.

**Why this genre:** the user explicitly wanted a terminal-window aesthetic (mac-style chrome originally, later flattened — see below) and researched two real sites for inspiration mid-build: zui.ooo (product designer, near-identical SYS.NAME/uptime/whoami pattern — strong validation this genre fit was right) and 2xa.studio (generative-art studio, dual-city clock header). See [[feedback-original-not-copied]] for the hard boundary that came up repeatedly during this research.

**Design decisions (current state, don't revert without being asked):**
- Background is pitch black (`--page-bg`/`--term-bg` = `#000000`), no warm radial-gradient tint (removed on request).
- TerminalWindow is flattened — no boxed card (no background/border/shadow/border-radius), no mac traffic-light dots. Just a thin divider under the path label. User explicitly asked to remove the "boxed" look so content merges into the page background.
- Single font: Geist Mono (variable, all weights) for everything — body AND headings, hierarchy via weight only. A prior attempt used Silkscreen (pixel/bitmap font) for headings; user rejected it as illegible/gimmicky. Do not reintroduce a second display font without being asked.
- Colors: `--term-accent` #ff5a2e (red-orange, primary), `--term-mint` #bcd6ad (secondary — now also Nia's color), `--term-fg` warm cream #f4ede1.
- Subtle grain texture (`.grain` in globals.css, SVG turbulence, opacity 0.05) is still present — wasn't asked to be removed even when background went pitch black.

**Key components and their current behavior:**
- `BootIntro.tsx` — plays on every fresh page load/reload (NOT sessionStorage-gated; that was removed because it made the intro seem broken/invisible on repeat visits). ~1.65s total. Dotted-frame "establishing connection" scene (globe → pulsing link dots → laptop, via `DotIcon`/`lib/dotIcons.ts` procedural bitmaps), then a real progressive-reveal typewriter (`TypedLine`, NOT framer-motion opacity-stagger — that approach was a bug, see [[feedback-dev-verification-quirks]]) typing "ACCESS GRANTED" starting at 0.4s, ~35ms/char, with a `|` cursor that genuinely trails the typed text. Overlay background is opaque (`var(--page-bg)`) — a transparent/`pointer-events:none` version (introduced outside this session at one point) looked broken and was reverted.
- `Mascot.tsx` ("Nia") — original procedurally-generated pixel creature (`lib/mascotBitmap.ts`, 17x18 grid), positioned fixed, wanders to a random x position every ~4.5s, blinks periodically, click/Enter-to-greet (random line in a speech bubble). Visible on mobile at `scale(0.5)` (not hidden — was 0.7x, shrunk further on request). Respects `prefers-reduced-motion`. **Positioning uses `top: calc(100dvh - 104px)`, NOT `bottom: 14px`** — this was a real bug, not just a style choice: on the mobile-emulated viewport in this dev environment, `window.innerHeight` (978) didn't match the actually-visible viewport (`document.documentElement.clientHeight`/`visualViewport.height`, both 812) — a well-known mobile-browser quirk where `position: fixed; bottom: Xpx` resolves against the *large* viewport (assumes browser chrome hidden) rather than what's actually on screen, silently pushing bottom-anchored fixed elements off-screen. `dvh` tracks the real visible viewport and isn't subject to this mismatch. If Nia (or any other `position: fixed` element) ever seems to vanish on a specific device/viewport again, check `window.innerHeight` vs `document.documentElement.clientHeight` first before assuming it's a z-index/overflow issue — confirmed via `getBoundingClientRect()` on the actual element, not by trusting a full-page screenshot (which renders fixed elements frozen at one pixel offset in the stitched image and can visually look wrong — "mid-content" — even when the real viewport-relative position is correct; `getBoundingClientRect()` is scroll/stitching-independent ground truth). Idle animation is a `steps(4)` squash-bounce (translateY+scaleX/Y), not smooth easing — smooth interpolation on a crisp pixel grid looks blurry, discrete steps read as authentic sprite animation. **Redesigned twice already**, both times from vague feedback ("does not look that great" → asked what specifically → got "shape, size, color, AND animation, no reference, use your judgment" → full redesign; then "give nia legs also" as a targeted follow-up once the shape was closer). Current design: round ears, wide-oval body, gold `#f2c14e`, 5px cells, and a dedicated leg band (bottom 4 rows of the grid fully overridden — not just added to — to two 3px-wide leg stubs; the body ellipse must stop *before* this band or a stray body pixel leaks into the leg gap, hit this bug once already). If more Nia feedback comes in, ask what specifically before changing things blindly — the pattern that works for this user is: ask first when feedback is vague, act directly when it's specific (e.g. "give her legs" didn't need a clarifying question).
- `CommandLine.tsx` — real interactive shell at the bottom of every page: `help`, `whoami`, `ls`, `cd <section>`, `cat projects`, `cat posts`, `contact`, `clear`. `cd` actually navigates via the router. Command submission also fires `playCommandBlip()`.
- `lib/sound.ts` — a small sound system, added because the user asked for "system sounds" then explicitly said **default to ON with a minimal sound, not muted** (don't default-mute like a typical "add a mute toggle" instinct would). Pure Web Audio API synthesis (sine tones + a noise-buffer click), no audio asset files — matches the site's "everything procedurally generated" ethos. `isSoundEnabled()`/`setSoundEnabled()` persist via `localStorage` key `portfolio-sound-enabled` (default true when unset), `SoundToggle.tsx` lives in `StatusBar`. Four sounds wired in: `playBootChime()` (BootIntro start), `playKeyClick()` (once per typed character — both `Prompt.tsx`'s `$ whoami`-style typing and BootIntro's "ACCESS GRANTED" `TypedLine`), `playCommandBlip()` (CommandLine submit), `playGreetChirp()` (Nia's click-to-greet). Known, unfixable limitation: the very first cold page load with zero prior interaction on the origin can have the boot chime silently blocked by the browser's autoplay policy — expected platform behavior, not a bug, works normally after that.
- `SysHeaderBar.tsx` — two-column system readout (left: SYS.USER/NODE/STATUS; right: live UPTIME (ticking from `profile.launchDate`)/SESSION/STATUS), persistent across all pages via `TerminalWindow`.
- `PageGlitch.tsx` — wraps the About page only (not site-wide) in a periodic (~7s cycle, ~200ms burst) CSS-only RGB-split + jitter glitch via `filter: drop-shadow(...)`, not DOM duplication — works on arbitrary real content without accessibility issues.
- `lib/asciiPortrait.ts` — generated from the user's own real cropped photo via `scripts/img-to-ascii.mjs` (contrast-stretch + Floyd-Steinberg dithering + ~70-char density-ordered ramp — NOT the original naive linear-ramp version, that looked like a gray blob). Regenerate anytime: `npm run ascii -- <path-to-photo>`. Current source photo is cropped tight to head/shoulders (`C:\Users\dines\Downloads\profile-cropped.jpeg`, derived from `profile  passport image .jpeg`).
